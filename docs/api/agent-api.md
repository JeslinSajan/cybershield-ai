# Agent API Contract

Base path: `/api/v1`

This file documents the non-human Agent actor only. It is intentionally separated from human user endpoints. Agent routes must authenticate with Agent credentials, not with a human JWT; they are scoped only to Agent operations and never to user, role, or system settings actions.

## FR Traceability
- FR-4.1: enrollment token generation by Administrator
- FR-4.2: Agent registration and credential issuing
- FR-4.3: heartbeat reporting
- FR-4.4: offline detection
- FR-4.5: Agent revocation
- FR-4.6: credential rotation
- FR-5.1: authorized scan initiation via online Agent
- FR-8.1: log collection
- FR-7.1: interface statistics
- FR-7.2: health metrics

## Agent Isolation Rules
- Agent endpoints accept Agent credentials only.
- Agent routes must not expose user account objects, role metadata, or system settings payloads.
- The stable identity is `agents.id`; `agents.hostname` is mutable metadata and is never used as the system identity.

## Error Envelope

```json
{
  "error": {
    "code": "AGENT_NOT_AUTHORIZED",
    "message": "The provided Agent credential is invalid or expired.",
    "details": []
  }
}
```

## Endpoints

### POST /agents/enrollment-token

- Auth requirement: JWT required
- Authorization: Administrator only
- Request schema:

```json
{
  "agent_name": "warehouse-host-01",
  "expires_in_minutes": 60
}
```

- Response schema:

```json
{
  "token": "time_limited_enrollment_token",
  "expires_at": "2026-08-24T13:00:00Z"
}
```

- Success status: `201 Created`
- Error statuses: `400 Bad Request`, `401 Unauthorized`, `403 Forbidden`
- Notes: The token is generated by the backend for a new Agent, matching FR-4.1. It is not stored as a user record and not exposed beyond the enrollment flow.

### POST /agents/register

- Auth requirement: Agent credential required after token issuance
- Authorization: Agent actor only
- Request schema:

```json
{
  "enrollment_token": "time_limited_token",
  "name": "warehouse-host-01",
  "hostname": "warehouse-host-01",
  "version": "1.0.0",
  "status": "PENDING"
}
```

- Response schema:

```json
{
  "id": "uuid",
  "organization_id": "uuid",
  "name": "warehouse-host-01",
  "hostname": "warehouse-host-01",
  "status": "PENDING",
  "version": "1.0.0",
  "credential": {
    "id": "uuid",
    "type": "token",
    "expires_at": "2026-08-25T12:00:00Z",
    "is_active": true
  }
}
```

- Success status: `201 Created`
- Error statuses: `400 Bad Request`, `401 Unauthorized`, `403 Forbidden`, `409 Conflict`
- Notes: The response contains Agent-only credentials and Agent state; it does not include any user role or settings data.

### POST /agents/heartbeat

- Auth requirement: Agent credential required
- Authorization: Agent actor only
- Request schema:

```json
{
  "agent_id": "uuid",
  "timestamp": "2026-08-24T12:30:00Z",
  "status": "ONLINE",
  "version": "1.0.0",
  "cpu_percent": 36.4,
  "memory_percent": 58.1,
  "details": {
    "disk_usage_percent": 43,
    "network_status": "ok"
  }
}
```

- Response schema:

```json
{
  "agent_id": "uuid",
  "status": "ONLINE",
  "last_heartbeat_at": "2026-08-24T12:30:00Z",
  "updated": true
}
```

- Success status: `200 OK`
- Error statuses: `400 Bad Request`, `401 Unauthorized`, `403 Forbidden`, `404 Not Found`
- Notes: This maps to `agent_heartbeats` plus `agents.last_heartbeat_at` and supports FR-4.3 and FR-4.4.

### GET /agents/tasks

- Auth requirement: Agent credential required
- Authorization: Agent actor only
- Request schema: none
- Response schema:

```json
[
  {
    "id": "uuid",
    "organization_id": "uuid",
    "agent_id": "uuid",
    "scan_type": "discovery",
    "status": "PENDING",
    "target_scope": "192.168.1.0/24",
    "created_at": "2026-08-24T12:00:00Z"
  }
]
```

- Success status: `200 OK`
- Error statuses: `401 Unauthorized`, `403 Forbidden`
- Notes: This is the Agent-side retrieval of pending scans. The line-of-business object is the `scans` record.

### POST /agents/tasks/{task_id}/status

- Auth requirement: Agent credential required
- Authorization: Agent actor only
- Request schema:

```json
{
  "status": "RUNNING",
  "started_at": "2026-08-24T12:31:00Z",
  "details": {
    "progress_percent": 25
  }
}
```

- Response schema:

```json
{
  "id": "uuid",
  "status": "RUNNING",
  "updated_at": "2026-08-24T12:31:00Z"
}
```

- Success status: `200 OK`
- Error statuses: `400 Bad Request`, `401 Unauthorized`, `403 Forbidden`, `404 Not Found`
- Notes: This represents Agent task-status reporting; it is not a user mutation endpoint.

### POST /agents/results

- Auth requirement: Agent credential required
- Authorization: Agent actor only
- Request schema:

```json
{
  "scan_id": "uuid",
  "device_id": "uuid",
  "result_type": "ports",
  "raw_payload": {
    "ports": [22, 80, 443],
    "services": [
      { "port": 22, "service": "ssh" },
      { "port": 80, "service": "http" }
    ]
  }
}
```

- Response schema:

```json
{
  "id": "uuid",
  "scan_id": "uuid",
  "device_id": "uuid",
  "result_type": "ports",
  "created_at": "2026-08-24T12:45:00Z"
}
```

- Success status: `201 Created`
- Error statuses: `400 Bad Request`, `401 Unauthorized`, `403 Forbidden`, `404 Not Found`
- Notes: This is the Agent upload path for authorized discovery or vulnerability evidence. The backend then normalizes it into `scan_results` and downstream tables.

### POST /agents/{agent_id}/revoke

- Auth requirement: JWT required
- Authorization: Administrator only
- Request schema: none
- Response schema:

```json
{
  "id": "uuid",
  "is_active": false,
  "revoked_at": "2026-08-24T12:50:00Z"
}
```

- Success status: `200 OK`
- Error statuses: `401 Unauthorized`, `403 Forbidden`, `404 Not Found`
- Notes: This matches FR-4.5 and the `agent_credentials.revoked_at` / `is_active` model.

### POST /agents/{agent_id}/rotate-credential

- Auth requirement: JWT required
- Authorization: Administrator only
- Request schema: none
- Response schema:

```json
{
  "agent_id": "uuid",
  "credential_id": "uuid",
  "expires_at": "2026-08-25T12:00:00Z",
  "is_active": true
}
```

- Success status: `200 OK`
- Error statuses: `401 Unauthorized`, `403 Forbidden`, `404 Not Found`
- Notes: This supports FR-4.6 without forcing full re-enrollment.
