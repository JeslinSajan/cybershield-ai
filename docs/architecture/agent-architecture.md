# CyberShield AI - Agent Architecture

**Version:** 2.0  
**Phase:** 2 of 27 - System Architecture Design  
**Scope:** Current local-first MVP

## Role and Boundary

The CyberShield Agent is a restricted, non-human actor running on an authorized host. It collects only authorized security data and exchanges it with the FastAPI Backend over HTTP/HTTPS REST. It has no dashboard access and is not a user role.

```text
+------------------------------------------------------------------+
| CyberShield Agent (authorized host)                              |
|                                                                  |
|  +------------------+  +-------------------+  +----------------+ |
|  | System Collector |  | Network Discovery |  | Scanner        | |
|  +------------------+  +-------------------+  +----------------+ |
|  +------------------+  +-------------------+  +----------------+ |
|  | Log Collector    |  | Monitor           |  | Detection      | |
|  +------------------+  +-------------------+  +----------------+ |
|                                                                  |
|  +--------------------------------------------------------------+ |
|  | API Client: credential, REST transport, task/status exchange | |
|  +--------------------------------------------------------------+ |
+----------------------------------+-------------------------------+
                                   | Agent-scoped REST only
                                   v
                         +----------------------+
                         | FastAPI Backend      |
                         +----------------------+
```

## Internal Modules

### System Collector

Uses `psutil` to collect CPU, RAM, disk, uptime, and network-interface statistics. It packages timestamped metrics with the Agent identity for authorized upload.

### Network Discovery

Runs Nmap against networks configured and authorized by the Administrator. It reports IP address, MAC address where available, hostname, vendor where available, open ports, and services. It does not choose arbitrary targets.

### Scanner

Performs port scanning and service/version detection on discovered devices. It matches results against the local or cached CVE dataset, assigns Low/Medium/High/Critical severity, and includes remediation recommendations. It does not exploit vulnerabilities.

### Log Collector

Reads authorized SSH authentication logs and Linux syslog entries, parses them, and uploads source data for Backend normalization. Typical MVP sources are `/var/log/auth.log` and `/var/log/syslog` on Linux hosts.

### Monitor

Schedules heartbeats and collection intervals, tracks local health, and reports CPU/RAM and Agent component status. The Backend marks an Agent OFFLINE after the configured heartbeat timeout.

### Detection

Performs only local Agent-side validation and collection-time filtering needed for reliable uploads. Authoritative threat detection, risk scoring, and alert creation occur in the Backend so rules and audit records remain centralized.

### API Client

The only network-facing module. It uses `httpx` to register with an enrollment token, authenticate subsequent requests with the Agent credential, send heartbeats, upload authorized metrics/discovery/vulnerability/log data, fetch scan tasks, and report task status. Transient failures may be retried and queued locally.

## Allowed Agent Operations

| Operation | Direction | Purpose |
|---|---|---|
| Register | Agent -> Backend | Exchange a valid time-limited enrollment token for an Agent credential |
| Authenticate | Agent -> Backend | Present the Agent credential on subsequent requests |
| Heartbeat | Agent -> Backend | Report identity, timestamp, version, status, and health |
| Upload authorized data | Agent -> Backend | Send metrics, discovery, vulnerability, and normalized/raw log data |
| Receive scan tasks | Backend -> Agent | Fetch Administrator/Analyst-authorized discovery or vulnerability work |
| Report task status | Agent -> Backend | Report accepted, running, completed, or failed task state |

## Explicitly Outside the Boundary

The Agent cannot access user management, roles or permissions, system settings, or the dashboard. It cannot read another organization's data, impersonate a human user, or connect to PostgreSQL directly. The Backend validates Agent ownership, organization scope, task authorization, payloads, and credentials on every request.

Agent credentials are separate from user JWTs. Enrollment uses a time-limited token generated by an Administrator; credentials can later be revoked or rotated. Only systems and networks explicitly authorized for the project may be collected or scanned.

## Local Failure Behavior

When the Backend is temporarily unavailable, the Agent records bounded local retry data and retries later. It must not silently expand its scan scope. The Backend remains the source of truth for task state and accepted data.
